# hfsnet 管理ツールの対応範囲

[English](MANAGEMENT.en.md) | [日本語](MANAGEMENT.md)

TCPPACK の管理ツール4本（ifconfig.x / netstat.x / inetdconf.x /
arp.x）について、オプションごとの本来の意味と、hfsnet での
対応範囲をまとめます。

記号の意味は次のとおりです。

- ○: 使えます
- △: 動作しますが、意味が表示と台帳（設定値の保持）に
  限られる、または一部が未検証です
- ×: 未対応です

前提として、hfsnet では TCP/IP の処理一式（スタック）が
ホスト側のアプリにあるため、ゲスト側の設定は実通信に
影響しません。詳しくは README の「ゲスト側の設定について」
を参照してください。ここでの △ の多くはこの理由によります。

動作確認の状況（2026-11-22 時点）: 表示系は XEiJ と
XM6 TypeG で確認済みです。WebX68k は確認中、実機は未確認です。

## ifconfig.x（インターフェースの設定と表示）

書式: `ifconfig <名前> [アドレス] [netmask <値>]
[broadcast <値>] [up|down]`

インターフェース名は小文字で指定します（hf0 / lp0）。
大文字では "no such interface" になります。名前も引数も
無しで起動すると、無言で終了します。この版の ifconfig には
一覧表示（-a のような）や、mtu などを変えるスイッチは
ありません。

- **表示のみ（名前だけ指定）: ○**
  フラグ、IP アドレス、ネットマスク、ブロードキャスト
  アドレスを表示します
- **アドレスの指定: △**
  台帳に保持され、表示に反映されます。実通信の送信元
  アドレスはホストのもののままで、変わりません。
  アドレスはホスト名でも指定できます（名前からアドレスを
  引く処理はホスト側で行われます）。2回以上指定すると
  警告が出て、最後の指定が有効になります
- **netmask <値>: △**
  台帳に保持されます。省略時はアドレスのクラスによる
  既定値（クラス A は /8、B は /16、C は /24）になります
- **broadcast <値>: △**
  台帳に保持されます。省略時は「アドレス | ~ネットマスク」
  になります
- **up: △**
  台帳の UP フラグを立てます。表示は
  `flags=15<UP,NOARP,BROADCAST>` のようになります。
  RUNNING フラグは立ちません（これは ifconfig 側の仕様で、
  実スタックではドライバ側が立てるものです）
- **down: ○**
  インターフェースを落とします。表示は
  `flags=14<DOWN,NOARP,BROADCAST>` になります。
  ただし台帳上の状態変化であり、hfsnet の通信自体は
  止まりません

## netstat.x（ネットワークの状態表示）

オプションは `-f -I -i -n -p -r -s -w` の8つです。

- **引数なし / -f inet（接続一覧）: ○**
  現在の接続を、プロトコル、送受信キュー、自側と相手の
  アドレス、TCP の状態つきで表示します。接続が無い状態で
  無言で正常終了することは確認済みです。接続がある状態での
  一覧表示そのものは未検証です
- **-f local: （元の仕様）**
  同じ機械の中の通信（UNIX ドメインソケット）用ですが、
  TCPPACK にその仕組みは無く、元の実装でも
  "Sorry, not supported." と表示するだけです
- **-i（インターフェース一覧）: ○**
  インターフェースごとに MTU、ネットワーク、アドレス、
  受信パケット数（Ipkts）、受信エラー（Ierrs）、
  送信パケット数（Opkts）、送信エラー（Oerrs）、
  衝突（Coll）を表示します。Ipkts と Opkts は、ゲストが
  数えたソケット送受信の成功回数で、本物の数字です。
  Ierrs / Oerrs / Coll は常時0です（エラーや衝突は
  ホスト側や物理層で起きるため、ゲストからは観測
  できません）。アドレスの名前変換は働かず、常に
  数字表示になります
- **-I <名前>: △**
  -i の表示を指定したインターフェースだけに絞ります。
  同じ表示経路ですが、明示の確認はしていません
- **-n（名前変換の禁止）: △**
  hfsnet ではもともと常に数字表示なので、付けても
  付けなくても同じ結果になります
- **-r（経路表）: ○**
  宛先、ゲートウェイ、フラグ（U = 有効、G = ゲートウェイ
  経由、H = ホスト宛て）、Use（その経路で送った
  パケット数）、出口インターフェースを表示します。
  Use は常時0です（経路参照のたびに増やす処理を
  入れていないため）。G フラグは、inetdconf.x で
  デフォルトルータを設定した後に立つようになります
- **-s（プロトコル統計）: （元の TCPPACK でも未実装）**
  IP / ICMP / UDP / TCP ごとの統計を表示するための
  ものですが、この版の netstat ではフラグを立てるだけで
  どこからも読まれておらず、何も表示されません。
  ドライバ側の統計情報（MIB）を実カウンタ化しても、
  この netstat では表示されるようにはなりません
- **-w <秒数>（継続監視）: △**
  指定した秒数ごとに、インターフェースのカウンタの
  増分と累計を繰り返し表示します。カウンタを読むだけ
  なので仕組み上は動作しますが、未検証です。監視対象の
  既定は一覧の先頭のインターフェースで、hfsnet では
  lp0（ループバック）になるため、hf0 を見たいときは
  `-I hf0 -w 1` のように組み合わせてください
- **-p: （元の TCPPACK でも未実装）**
  ソースに TODO と書かれた予約枠で、何もしません

## inetdconf.x（ドライバへの設定）

オプションは「+で設定、-で解除」の組で、複数を1回の
起動に並べて書くこともできます（例:
`INETDCONF.X +router 192.168.1.1 +dns 192.168.1.1 -rip`）。

- **引数なし（現在の設定を表示）: ○**
  デフォルトルータ、RIP の状態、DNS サーバの一覧、
  ドメイン名の4項目を表示します。アドレスは名前変換
  されず、常に数字表示です
- **+router <アドレス>: ○**
  デフォルトルータ（宛先の分からないパケットの渡し先）
  を設定します。アドレスはホスト名でも指定できます。
  設定時はまず「そのルータへの経路があるか」を確認し、
  無ければ "No route for ..." というエラーになります。
  設定と表示の読み戻しまで確認済みです
- **-router: △**
  デフォルトルータの設定を解除します。台帳の解除処理は
  実装済みですが、読み戻しの明示確認はしていません
- **+dns <アドレス>: ○**
  DNS サーバ（名前から IP アドレスを引くための
  問い合わせ先）を登録します。後ろに空白で並べれば
  複数を一度に登録できます。台帳は最大4件です。
  設定と読み戻しは確認済みです。ホスト名での指定は
  未検証です
- **-dns <アドレス>: △**
  登録した DNS サーバを削除します。実装済みですが、
  読み戻しの明示確認はしていません
- **+domain <名前> / -domain: △**
  自側のドメイン名の設定と取り消しです。63文字までで、
  超えるとアプリ側がエラーにします。設定・保持・表示の
  処理は実装済みですが、実際に値を入れた表示確認は
  していません
- **+rip / -rip: △**
  RIP（Routing Information Protocol、近くのルータ同士で
  経路情報を交換する仕組み）の動作と停止です。台帳の
  フラグの読み書きを実装し、表示が「Off」になることは
  確認済みです。「On」表示の経路は未検証です。
  なお、inetd.x では RIP は既定で動作していますが、
  hfsnet では経路交換を一切行わないため、初期表示は
  Off にしています
- **不明なオプション: （アプリ側の動作）**
  使い方（usage）と "Illeagal option" というエラーが
  出ます（綴りは原文どおり）。usage の文章には元の
  バグがあり「+route」と書かれていますが、実際に
  効くのは「+router」です

## arp.x（ARP テーブルの表示と制御）

ARP（Address Resolution Protocol）は、IP アドレスと
ハードウェアアドレス（MAC アドレス）の対応を扱う
仕組みです。作り上の特徴として、オプションは最初の
1つしか処理されません。

- **引数なし: （アプリ側の動作）**
  使い方（4行）を表示します
- **arp <ホスト名またはIPアドレス>（1件表示）: △**
  そのホストのエントリを「名前 (IPアドレス) at
  ハードウェアアドレス」の形で表示します。hfsnet では
  名前解決までは正しく進み、常に「-- no entry」に
  なります
- **-a（全件表示）: ○**
  テーブルの全エントリを一覧します。hfsnet では
  テーブルが空のため、無言で正常終了します。
  ドライバ側は「17本のバケツ配列」という格納形式で
  テーブルを渡す決まりで、この受け口を実装して
  あります（NULL を返すと -a が落ちます）
- **-d <ホスト>（削除）: △**
  エントリを消します。hfsnet では何も起きませんが、
  消す対象が無いため結果として正しい動作です
- **-s <ホスト> <ハードウェアアドレス>（手動登録）: △**
  対応を手で登録します。登録しても保持されません。
  直接経路のチェック（ゲートウェイ経由の相手には
  登録できない、という判定）を通過したあと、
  インターフェースにアドレス文字列の解釈処理が
  無いため、"Unable to convert hardware address,
  because iface can't handle it." と表示されて
  終わります
- **-f <ファイル>: （元の TCPPACK でも未実装）**
  受け口だけあって処理が無く、黙って無視されます

制限の本質は、ARP が LAN の中だけの仕組みだという
点です。inetd.x ではイーサネットドライバが実際に
ARP を送受信してテーブルが育ちます（通信した相手が
10分間残ります）が、hfsnet の実通信はホスト側の
スタックが担い、ARP テーブルはホストの OS が
持っています。ゲストからはそれが見えず、ゲスト側に
テーブルを作っても通信には使われません。
